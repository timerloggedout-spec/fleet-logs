## Q1: What is the recommended approach for creating branches when working on a new feature?

**Correct Option:** Create a new branch for the feature based on the main branch.

**Justification:** This approach ensures that the main branch remains stable and allows for isolated development of new features.

**Evidence:** "When working on a new feature, create a new branch based on the main branch."

## Q2: What is the recommended length of time for a feature branch to exist?

**Correct Option:** It should be short-lived, lasting hours or days to enable faster merging and feedback.

**Justification:** Short-lived branches reduce the risk of conflicts and allow for quicker integration of changes.

**Evidence:** "Feature branches should be short-lived, lasting only hours or days."

## Q3: What is a key benefit of using a consistent naming convention for branches?

**Correct Option:** It helps identify the branch's purpose at a glance and improves collaboration.

**Justification:** A clear naming convention makes it easier for team members to understand the purpose of each branch and facilitates better collaboration.

**Evidence:** "Using a consistent naming convention for branches helps identify their purpose at a glance and improves collaboration."
