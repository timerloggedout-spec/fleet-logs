## Answers to FreeCodeCamp Relational Databases v9 Lesson: "What Is a Pull Request, and How Do You Create One?"

**KEY Q1:** A request to pull changes from one branch into another branch.

**Q1:** What is a pull request in GitHub?

**A:**  A request to pull changes from one branch into another branch. 

**Justification:** This is the definition of a pull request given in the lesson: "A pull request (also known as a “PR”) is a request to merge changes from one branch into another branch."

**Lesson Evidence:** "A pull request (also known as a “PR”) is a request to merge changes from one branch into another branch."

**KEY Q2:** "Base" is the target branch; "compare" is the source branch.

**Q2:** In a pull request, what do the terms "base" and "compare" (or "head") refer to?

**A:** "Base" is the target branch; "compare" is the source branch.

**Justification:**  The lesson explains: "The base branch is the branch you want to merge the changes into (usually the main branch)." and "The compare branch is the branch that contains the changes you want to merge."

**Lesson Evidence:**  "The base branch is the branch you want to merge the changes into (usually the main branch)." ... "The compare branch is the branch that contains the changes you want to merge."

**KEY Q3:** Fork and Merge

**Q3:** Which of the following is NOT a merge strategy mentioned when merging a pull request on GitHub?

**A:** Fork and Merge

**Justification:** The lesson explicitly mentions Merge, Squash and Merge, and Rebase and Merge as merge strategies. Fork and Merge is not mentioned.

**Lesson Evidence:**  "GitHub provides three merge strategies:" ...

 - **Merge:** Creates a new commit that merges the two branches.
 - **Squash and Merge:** Combines all commits from the pull request into a single commit on the base branch.
 - **Rebase and Merge:** Rebases the pull request branch onto the base branch, then creates a merge commit.
