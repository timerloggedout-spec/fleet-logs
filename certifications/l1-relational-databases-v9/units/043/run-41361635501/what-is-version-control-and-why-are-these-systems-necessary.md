## Answers to FreeCodeCamp Relational Databases v9 Lesson: "What Is Version Control, and Why Are These Systems Necessary?"

**KEY Q1:** A snapshot of a specific state of your codebase.

**Q1:** What is a commit in Git?

**A:**  **(C) A snapshot of a specific state of your codebase.**

* **Justification:** A commit captures a point in time representation of the entire project, allowing you to revert to that exact state later.

* **Evidence:**  "Each time you commit, Git takes a snapshot of the entire project at that point in time."

**KEY Q2:** They allow you to work on features in isolation.

**Q2:** Why are branches useful in version control systems like Git?

**A:** **(C) They allow you to work on features in isolation.**

* **Justification:** Branches enable developers to work on new features or bug fixes separately from the main codebase, preventing unfinished work from affecting the stable version.

* **Evidence:**  "Branches allow you to work on new features or fix bugs without affecting the main codebase."

**KEY Q3:** Docker

**Q3:** Which of the following is NOT mentioned as a version control system in the lesson?

**A:** **(D) Docker**

* **Justification:**  The lesson explicitly mentions Git and SVN as examples of version control systems, and Mercurial is implied as another example. Docker, while a valuable tool, is a containerization platform, not a version control system.

* **Evidence:**  The lesson discusses Git and SVN specifically, and refers to "other version control systems" in general terms, but does not explicitly mention Docker.
