## Answers to FreeCodeCamp Relational Databases v9 Lesson: "How Do You Contribute to Other People's Repositories?"

**KEY Q1:** Forking the repository.

**Q1:** What is the first step in the process of contributing to someone else's repository on GitHub?

**A:** Forking the repository.

**Justification:**  This creates a personal copy of the repository that you can modify without affecting the original.

**Evidence:** *"The first step in contributing to someone else’s repository on GitHub is to fork the repository."*

**KEY Q2:** git remote add upstream [URL]

**Q2:** After forking and cloning a repository, what command would you use to add the original repository as a remote?

**A:** git remote add upstream [URL]

**Justification:** This command establishes a connection to the original repository, allowing you to fetch updates and push changes back.

**Evidence:** *"Next, you need to add the original repository as a remote. This is done with the following command: git remote add upstream [URL]"*

**KEY Q3:** To fetch updates from the original repository.

**Q3:** What is the purpose of the upstream remote in the context of contributing to a repository?

**A:** To fetch updates from the original repository.

**Justification:** The upstream remote allows you to stay synchronized with the original repository's latest changes.

**Evidence:** *"The upstream remote is crucial for fetching updates from the original repository and keeping your forked copy up-to-date."*
